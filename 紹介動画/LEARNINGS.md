# 紹介動画制作で整理した内容

## 1. MMDirectEncoder の実装から確認した事実

動画内の記述は、すべて以下のソースで確認したものに限定しています。

### 動作の仕組み
- DirectShow の Transform フィルタ (`native-filter/src/ffmpeg_encoder.cpp`) として登録され、MMD の「AVI出力」でビデオ圧縮コーデックとして選択される。
- 受け取った RGB フレームを ffmpeg の stdin へパイプで送り、本来の出力ファイルを ffmpeg に直接書かせる。
- AVI 側には ffmpeg が stdout に出す最小品質の H.264 (`ultrafast`, `crf 51`) を返し、出力完了後に AVI を削除する (`StopStreaming`)。
- 出力先は AVI の保存先から拡張子だけを差し替えたパス (`PrepareExecutionPlan`)。
- MMD v9.32 のメモリから出力範囲・fps・WAVE 設定・WAV パスを読み取る (`mmd_host.cpp`)。このため v9.32 専用。
- 連番は MMD の開始フレーム番号から命名し、取得できない場合は 0 始まりで後から桁数を揃えて改名する。
- 音声は AVI 内の音声を優先し、無ければ MMD の WAV を開始フレームに合わせて切り出して結合する。MP4 は AAC、WebM は Opus、MOV は PCM。

### 出力形式とプリセット
- 対応形式: 動画 (透過なし) 7 種、動画 (透過あり) 3 種、連番画像 5 種の計 15 種。
- OpenEXR は ffmpeg を使わず OpenEXR ライブラリで直接書き出す (`encoder/exr_writer.cpp`)。
- プリセット 8 種 (`config/encoder_config.cpp` の `ApplyPreset`): 高品質 H.264 (CRF 18) / HEVC (CRF 20) / AV1 (CRF 24) / YouTube (H.264, GOP 60, Bフレーム 2) / 編集用 ProRes 422 HQ / 透過動画 ProRes 4444 / 静止画連番 PNG / カスタム。

### GPU エンコード
- 自動選択の優先順は NVIDIA NVENC → Intel QSV → AMD AMF → CPU (libx264 / libx265 / libsvtav1)。
- DXGI で GPU ベンダーを検出し、各エンコーダで実際にテストエンコードして利用可否を判定。結果は ini にキャッシュし、ffmpeg のファイル情報と GPU 構成が変わったときだけ再判定する。
- 10bit H.264、4:2:2 など GPU が扱えない設定は CPU へ自動で切り替える (`GpuSupports`)。
- ProRes / VP9 / 連番は常に CPU で処理する (`ValidateAndCorrect`)。

### 設定画面・導入・トラブル対応
- 設定画面は「基本設定」「詳細設定」「その他の設定」の 3 タブ。レイアウトは `ui/encoder_ui.rc`、表示言語は 自動 / 日本語 / English。
- インストーラー (Inno Setup) はユーザー単位で `%LOCALAPPDATA%` に導入し、管理者権限は不要。ffmpeg を同梱。
- インストール後に `MMDirectEncoderConfig.exe --selftest` を実行し、登録・ffmpeg・テストエンコード・EXR 書き込みを検査。
- 出力ごとに診断ログ (`latest.log` と `export_*.log`、直近 50 件) を保存し、失敗時は原因と対処をメッセージで表示する。

## 3. 制作方式

- 動画編集ソフトを使わず、HTML/CSS でシーンを作り、`render(t)` 関数で時刻 t の状態を JavaScript から決定的に設定する方式にした。CSS アニメーションに頼らないため、フレーム落ちやタイミングずれが起きない。
- Playwright で 1 フレームずつ JPEG (品質 95) で撮影し、ffmpeg の stdin へパイプして libx264 で圧縮する。中間ファイルを作らない。
- 設定画面は実機 (Windows + MMD) で撮影できないため、`.rc` のダイアログ定義 (DLU 座標) と `property_dialog.cpp` の既定値を基に HTML で再現し、動画内に「再現イメージ」と明記した。
- 配色はアイコン (黒地にシアンのグラデーション) に合わせた。

## 4. つまずいた点と対処

| 問題 | 対処 |
|---|---|
| 日本語が単語の途中で改行される | `word-break: auto-phrase` と `text-wrap: pretty` を指定し、要所は `<br>` で明示的に改行 |
| Noto Sans JP の幅で再現ダイアログのラベルが入力欄に重なる | ラベルを 16px に下げ、入力欄の開始位置を右へずらした |
| GPU シーンで全行にチェックを付けると「全 GPU が使える」と誤解される | チェックをやめ、優先順位の番号を順に走査するアニメーションに変更 |
| 強調枠の座標がタブ枠のオフセット分ずれた | 枠の座標をダイアログ本体基準 (タブ枠 left 20 / top 62 を加算) で計算し直した |
| クラウド環境から GitHub の raw ファイル (フォント) を取得できなかった | npm の `@fontsource-variable/*` パッケージでフォントを導入 |
| Unicode-range で分割されたフォントの読み込みが撮影に間に合わない | 撮影前に全シーンを一度表示して `document.fonts.ready` を待ち、フレームごとにも待機 |
| push が 403 で拒否された | GitHub 側の権限が復旧した後に再実行して成功 |

## 5. 今後の拡張案

- ナレーションを追加する場合は、音声ファイルを用意して ffmpeg の入力に追加し、各シーンの `data-start` / `data-end` を音声の長さに合わせる。
- 実機のスクリーンショットや操作録画が用意できれば、設定画面のシーンを差し替えると説得力が増す。
- 英語版は `index.html` の文言を差し替えるだけで同じ手順でレンダリングできる。
